# 일반 우회전 오분류 원인 점검 — 2026-09-27

새 학습 영상 27장을 추가해도 일반 우회전이 외부 맵에서 계속 실패해, 입력 표현과 모델의 구분 능력을 따로 시험했다. 학습·개발·외부 분할은 [보강 기록](targeted_supplement_20260927.md)과 같다. 실험 모델들은 FPGA 구현이나 주행용으로 채택하지 않는다.

## 영상 자체의 유사성

새 한쪽 차선 일반 우회전 7장을 해당 촬영 실행을 제외한 이전 학습 영상과 비교했다. 각 영상의 16×16 이진 입력에서 가장 가까운 영상은 `right` 5장, `sharp_right` 2장이었다. 16×16 명암, 64×64 이진, 64×64 명암 표현에서도 각각 5:2였다. [원본·16×16 최근접 영상 비교](right_turn_input_audit_20260927/new_right_nearest_review.png)와 [수치 결과](right_turn_input_audit_20260927/report.json)를 보관했다. 이는 1최근접 이웃 픽셀 비교로, CNN의 분류 성능이나 실차 조향 정답을 뜻하지 않는다.

개발 검증의 일반 우회전 32장 중 16×16 이진 최근접 학습 라벨이 `right`인 것은 17장, 3m case1의 22장 중 6장, 공식 타일 9장 중 2장이다. 64×64 이진에서는 각각 15장, 13장, 5장이었다. 맵과 표현에 따라 차이가 크므로 **16×16 정보가 모두 사라졌다고 볼 수 없고**, 해상도를 높이면 모든 환경에서 좋아진다고도 볼 수 없다. 서로 다른 맵의 원본 타일을 공유하는 경우가 있어 이 수치도 완전히 독립적인 일반화 평가가 아니다.

## 같은 분할에서의 입력 방식 실험

세 실험은 학습 1,069장과 동일한 개발·외부 분할, 같은 초기 seed와 조기 종료 규칙을 사용했다. `16×16 이진`은 현재 ULT-CNN이다. `16×16 명암`은 같은 구조와 1,440개 파라미터를 유지한다. `32×32 이진`은 Conv 뒤에 풀링을 하나 더 넣어 FC 크기와 **1,440개 파라미터를 유지**했지만, 초기 두 Conv가 처리하는 공간은 약 4배다. 이는 FPGA 계산량과 입력 인터페이스 변경을 동반하는 별도 구조 실험이다.

| 평가 | 16×16 이진 | 16×16 명암 | 32×32 이진 |
| --- | ---: | ---: | ---: |
| 개발 전체 | 225/385 | 205/385 | 233/385 |
| 개발 일반 우회전 | 18/32 | 19/32 | 18/32 |
| 공식 타일 전체 | 50/87 | 33/87 | 53/87 |
| 공식 타일 일반 우회전 | 0/9 | 1/9 | 0/9 |
| 3m case1 전체 | 4/38 | 9/38 | 6/38 |
| 3m case1 일반 우회전 | 0/22 | 7/22 | 0/22 |
| 혼합 상황 18번 일반 우회전 | 0/2 | 1/2 | 0/2 |

명암 입력은 일부 일반 우회전을 회복했지만 공식 타일 전체와 개발 전체가 크게 나빠졌다. 32×32는 전체 정답을 일부 늘렸으나 외부 일반 우회전은 여전히 0장이다. 따라서 **단순 해상도 증가를 채택하거나 FPGA 입력 규격을 바꿀 근거가 부족**하다. [명암 모델 결과](output_targeted_gray16_20260927/metrics.json), [32×32 모델 결과](output_targeted_binary32_20260927/metrics.json), [현재 이진 모델 결과](output_targeted_20260927/metrics.json)를 보관한다.

현재 이진 모델은 3m case1의 일반 우회전 22장을 `sharp_right` 12장, `sharp_left` 5장, `straight` 3장, `stop` 2장으로 예측한다. 공식 타일 일반 우회전 9장은 `sharp_right` 6장, `sharp_left` 2장, `straight` 1장으로 예측한다. **우회전 방향은 맞지만 강도를 과하게 예측하는 경우**와 **방향 자체가 틀리는 경우**를 분리해야 한다. 새 우회전 학습 영상도 7장 중 4장은 `sharp_right`, 3장은 `stop`으로 예측돼 현 CNN의 출력 경계가 맞지 않는다.

## 다음 판단 기준

사용자가 정한 구조대로 FPGA는 여섯 클래스를 출력하고 라즈베리파이가 실제 조향값을 정한다. 그러므로 `right`와 `sharp_right`의 경계는 Webots e-puck의 순간 바퀴 속도가 아니라 **실차에서 같은 화면에 필요한 조향량·회전 반경**으로 확인해야 한다. 현재 연결된 Windows 직렬 포트가 없어 실차 측정은 이 환경에서 수행하지 못했다. 그 전에는 새 오른쪽 장면을 모델 예측만 보고 재라벨링하거나, 명암/32×32 실험 모델을 배포하지 않는다.

실차 측정 자료를 얻으면 화면·차량 위치·진행 방향·속도·7/9 일반 조향과 4/6 급조향의 실제 PWM/서보각·회전 반경을 같은 시점에 기록한다. 이후 일반/급회전 라벨을 재검수하고, **새로운 별도 맵과 실차 영상**으로 최종 평가한다. 이미 여러 모델을 비교한 현재 외부 맵은 계속 개발 지표로만 사용한다.
