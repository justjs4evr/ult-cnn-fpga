# FPGA 전체 CNN 구현 기준 (실험용)

현재 목표는 카메라의 16×16 입력으로 ULT-CNN의 여섯 클래스만 FPGA에서 계산하고, 실제 조향값은 라즈베리파이가 결정하는 것이다. 이 문서는 RTL과 소프트웨어의 계산을 일치시키기 위한 기준이다. 사용 체크포인트 `output_visible_pair_20260927/best_model.pt`는 검증용 예시이며, 주행용 모델로 확정되지 않았다.

## 실행과 산출물

`fpga_reference.py`를 `ult_cnn_training`에서 `.venv\Scripts\python.exe .\fpga_reference.py`로 실행한다. `fpga_reference_output/reference_report.json`에 체크포인트 SHA-256, 계산 규칙, 텐서 형상, 평가 결과가 기록된다. 여덟 개의 가중치·bias `.hex` 파일과 클래스별 입력 및 층별 출력 `.hex` 파일은 **한 줄에 한 값, 행 우선 순서, 2의 보수**이다. 입력은 2자리, 나머지는 4자리 16진수이다. Conv 가중치는 출력 채널/입력 채널/행/열 순서, FC 가중치는 출력/입력 순서이다. 입력 벡터는 전처리가 끝난 16×16 바이트값이며 원본 카메라 JPEG가 아니다.

## 연산 계약

1. 라즈베리파이 또는 카메라 입력 경로가 학습과 같은 전처리를 수행한다: 상단 25% 제거, 흑백, 64×64 BOX, 127 이상 이진화, 16×16 BOX. 마지막 평균 축소 때문에 16×16 픽셀은 0 또는 255만 나오지 않을 수 있다.
2. 입력 바이트 `p`를 `round(p × 1024 / 255)`로 바꾼다. 입력·활성값·bias는 부호 있는 16비트 Q6.10, 가중치는 부호 있는 16비트 Q2.14이다.
3. Conv1(3개 3×3, zero padding 1) → ReLU → 2×2 max pool → Conv2(6개 3×3, zero padding 1) → ReLU → 2×2 max pool → FC1(96→12) → ReLU → FC2(12→6) 순서이다. PyTorch와 같이 Conv는 커널을 뒤집지 않는 상관 연산이다.
4. 각 출력에 대해 정수 곱을 누적한 후 14비트 우측 이동으로 가장 가까운 정수에 반올림한다. 정확히 중간값이면 0에서 먼 쪽으로 반올림한다. 그런 다음 해당 bias를 더하고, 필요한 층에서 ReLU를 적용하고, 부호 있는 16비트로 포화시킨다. 풀링은 최댓값이다.
5. FC2 출력의 최대값 인덱스가 최종 클래스이다. 동점이면 번호가 작은 클래스를 선택한다. 클래스 순서는 `straight, left, right, sharp_left, sharp_right, stop`이다. `confidence`나 softmax는 이번 FPGA 인터페이스에 포함하지 않는다.

550장의 개발·외부 평가 입력에서 정수 기준과 PyTorch의 최종 클래스가 **550/550** 일치했고, 네 계산층의 출력 포화는 **0회**였다. 이는 이 체크포인트의 이 입력 집합에 대한 수치 일치일 뿐이다. 실제 코스에서의 분류 정확도나 합성 가능성, 타이밍, FPGA 자원 사용량은 입증하지 않는다.

기존 `ult_cnn_개발 연구/ult_cnn_top.v.txt`는 구현 초안으로만 취급한다. 해당 파일은 학습 모델의 네 bias를 계산에 포함하지 않고, 현재 가중치 export도 bias와 층간 스케일을 제공하지 않는다. 참조하는 `ult_cnn_weights.v` 역시 아직 생성되지 않았다. 따라서 이 초안의 출력을 위 기준과 동일하다고 가정하면 안 된다. 다음 RTL 단계에서는 이 계약대로 bias·스케일·포화·메모리 읽기 순서를 구현하고, 제공한 여섯 입력 벡터의 **각 층 출력**을 시뮬레이션에서 대조해야 한다. 이후 합성 자원과 타이밍을 확인한다.
